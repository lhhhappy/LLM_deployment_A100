## 171/172的结论边界

056/057使用原dev N22；新长链/lite尚无两算子的成绩。算子的整段收益取决于目标操作的耗时占比、batch形状以及显存/缓存变化，换负载后这些比例会改变。固定工作量下若目标部分占比f、加速s，理想总加速为 `1/((1-f)+f/s)`；没有新负载的f不能算出总加速，更不能换算N@SLO。临近服务饱和时，执行时间的小幅变化也可能改变排队尾部。旧dev证据不足以否定新负载收益，也不足以承诺22/26。
