# 运行证据约定

`notes/experiments.md` 是实验结论与证据索引，`notes/queue.md` 是当前运行状态；本目录保存可复核的原始记录。编号目录沿用 `L<编号>-<名称>/`，历史目录不改名、不搬动，研究材料用主题目录。文档必须链接到实际文件。

每个新运行目录至少记录配置/代码版本、冻结数据标识与 SHA256、预热和 flush、派发与排空状态、错误数、服务日志路径。完整运行以原 harness 生成的 `raw*.jsonl`、`run*.json`、`report*.json` 和 score/verdict 收据为判分依据；保留完整服务日志、派发/flush 收据及传输校验收据。窗口诊断放在 `opening/` 或 `window/`，其 raw、快照、共同请求对照和窗口门收据只说明该窗口。不得用窗口产物覆盖完整档文件。

状态词要按证据解释：`PENDING`/`RUNNING` 是未完成；`OPEN` 表示测量窗口或请求仍未闭合；`DRAINED` 只表示指定派发窗口已排空，是机制诊断；`VALID PASS`/`VALID FAIL` 仅用于原 harness 输入完整、每条预期请求恰好一次且 flush/合同通过的完整运行；任何缺失、重复、数据/配置不匹配、启动机制不符或 harness 校验失败均为 `INVALID`；人为中止记 `ABORTED`。`INVALID` 与 `OPEN` 不得当作成绩或与完整运行比较，`DRAINED` 也不得写成整档通过/失败。

归档时保留原文件名和目录结构，生成逐文件 SHA256 清单；复制后逐项核对哈希，记录归档位置与清单。原始 raw、服务日志、派发/flush、正式状态及原 harness 收据不可因整理而删除。确认过时或重复的派生物也先核引用、用途和哈希，再由维护者单独清理；禁止按文件名或时间戳推断可删。

新生成的汇总、图表、坏例表、brief 和分析 JSON 应能从保留的 raw/收据复算，并标记生成命令或脚本版本；它们是派生物，不替代原始记录。临时脚本和中间结果只在确实支持复核时保留，避免把操作入口藏在证据目录。
