# Engine 128 review (3aad9c4f)

Verdict: **do not run this probe**. The code-path checks below passed, but an independent workload review found that the proposed family benefit relies on groups the scheduler usually cannot observe. Engine 128 stays on its separate branch; no Pod job was queued.

The LPM holdback path records each follower's shared prefix length. `link_families` now requires matching token prefix, `extra_key`, and `cache_salt`, consistent with `RadixKey`; the first revision (`dd64e9a8`) could credit a different cache namespace and was corrected in `3aad9c4f`. Links are cleared on a successful `/flush_cache`. The unit-work value changes only the within-tier order of a family leader; 124 still judges whether that leader can meet its deadline using its own remaining work. Rank 0 computes the plan and broadcasts the RID order, so rank-local clocks cannot split TP ranks. Enabling 128 without 124 or LPM is rejected at startup. With 128 off, the new shared-length record is unused.

Verified in the frozen worktree: `test_ax_deadline.py` 32/32, `test_ax_admission_scheduler.py` 24/24, `test_sched_protect_chain.py` 32/32, and `git diff --check 7c6cb634 3aad9c4f`. The probe script `v3_open_124_128_n26.sh` differs from 104 only by engine commit, `SGLANG_AX_DEADLINE_FAMILY=1`, and its mechanism expectation.

Why the probe was withdrawn: LPM performs its in-batch comparison only when a request's real cache match is at most `IN_BATCH_PREFIX_CACHING_CHECK_THRESHOLD=32` tokens (`schedule_policy.py`). In 104, the first chain start had already published about 8k of the common prefix when other starts arrived 1–2 seconds later, so they were real cache hits and never entered 128's `ax_shared` groups. LPM also groups by the prefix shared with a previously admitted request, not by the offline `prefix_family_id`; the offline 12→7 missed-start estimate used a different grouping and is invalid for this mechanism. The independent review found the visible 62bf0fac leader's family work per request was about 23.5k, still behind 14–19k single starts. A weakly shared follower can increase that value, and a family leader too large to finish in one round can suppress 124's parking of a smaller eligible waiter. These are design limitations, not bugs caught by the CPU tests. Any later family-aware proposal must first derive its groups from actual scheduler-visible matches and model the admission/parking constraints.
