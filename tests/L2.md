# L2 — Trisol 8×A100 self-test (提测)

## How it works
1. **One resident service.** `lh-arena-sess-a` (team arena, cluster w1, 8×A100, organizer base image)
   waits in Trisol's admission queue until cards free up. Once admitted, the cards stay ours until the
   daemon releases them (after the queue is empty and idle for 3 h).
2. **The daemon runs everything.** `scripts/trisol_test_daemon.py` runs on the GPU box in tmux
   (`arena-daemons`), so it keeps going with the laptop closed. When the service is admitted, it
   runs the approved items in `tests/queue/` one by one. For each item it:
   - applies the item's patches to the base inside the pod;
   - starts SGLang with the item's command and env;
   - climbs the dev-set ladder;
   - writes the results to `runs/NN-slug/` and `data/trisol_tests.json`.

   It never starts a new admission queue between items.
3. **Same code as L3.** A config applies to the organizer base exactly the patches our submitted
   image applies (same files, `patch -p3 --fuzz=0`), with the submission's own command and env.
   Only the port and policy flag are set per config. So an L2 number is a measurement of the
   thing we submit.

## Commands (run from the repo root, locally or on the GPU box)
```
python3 scripts/l2.py configs          # what can be tested
python3 scripts/l2.py add img_b        # queue + approve (runs automatically)
python3 scripts/l2.py ls               # queue status;  details: python3 scripts/test_status.py
python3 scripts/l2.py pause|resume     # stop/start the whole queue
```
Options for `add`:
- `--hint N`: where the fast ladder search starts (default 14).
- `--levels 6,10,14`: run exactly these rungs instead of searching.
- `--budget MIN`: time box in minutes (default 300).
- `--slug NAME`: set the item name, for example to repeat a config.

## Testing a new idea
1. **Code change:**
   - Write the change against the organizer base source (`build/base_src/`).
   - Save it as `patches/1NN-name.patch` in `a/python/sglang/...` diff form, plus a short `1NN-name.md`.
   - It stacks on 000.
2. **Flag or env change only:** copy a profile to `submission/candidate-bX-<name>.json` (submission
   format) and edit its command or env there.
3. **Register and queue:**
   ```
   python3 scripts/l2.py new img_x --profile submission/candidate-bX-<name>.json --patches 000,1NN [--policy lpm] [--d1]
   python3 scripts/l2.py add img_x
   ```
4. **Sync** the repo to the GPU box (`/sjtu/linhang/arena/repo`). The daemon picks the item up on
   its next poll.

## Promoting to L3
A config that beats the current best at L2 is built into an image. `build_image.sh` uses the same
patch list as the config. The image then goes through `scripts/submit_official.sh`, within the
2-per-day quota.

Every L3 result is recorded next to its L2 twin in `notes/submissions.md`. That is the L2→L3
calibration table.

## Queue policy (decision 28)
Queue items are mechanism changes (code patches), each with a hypothesis tied to a measured bottleneck.
Flags and env are only adjusted as part of such a change, never swept on their own. The withdrawn
35-item parameter sweep is in `tests/queue_archive/param_sweep_0922/`.
Launch flags are not yet confirmed on the base: the first item's inspection saves
`runs/01-img-a/inspection/report.json` (`server_help`) and `base_src.tgz` (base sources).
