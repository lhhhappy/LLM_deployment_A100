# TIERS.md — 三级验证体系（用户定义，2026-09-22）

一个改动从想法到拿分，依次经过三级；**上一级没过，不进下一级**。每一级只回答它能回答的问题。

| | **L1 2 卡自测** | **L2 提测（Trisol 8 卡）** | **L3 正式提交** |
|---|---|---|---|
| 在哪 | GPU 开发机 2×A100（`/sjtu/linhang/arena`） | Trisol arena/w1，8×A100，常驻服务 | 主办方平台 |
| 模型 | 随机权重替身（3 KDA + 1 MLA，无 DSA） | **真实 GLM-5.3-Flash** | 真实 |
| 引擎 | 我们编译的 SGLang v0.5.20 + 补丁 | 主办方底包 + 现场打**与提交镜像相同**的补丁（000/1xx），用提交的原文命令和环境变量 | 我们构建的镜像 + 提交的原文命令 |
| 数据 | 用例集 `cases/*`（真实开发集 prompt） | 原版开发集（`run_dev.py`），或用例集 | 隐藏正式集 |
| **能确认** | 补丁能加载能跑、不崩；缓存命中行为（cached_tokens）；接口合规（flush/SSE/时间戳）；不变量（单 partial、无泄漏）；关掉开关时与原版一致 | 补丁能否打上**底包**；真实性能：TTFT/TPOT、各门 p95、开发集临界 N；方案之间的**相对**好坏；能力抽检；和模拟器对账 | **成绩本身**：N@SLO、tpot_mean、能力分 |
| **不能确认** | 任何性能数字；DSA 路径；能力分 | 正式集上的绝对 N（开发集构成不同）；每档 4 小时长跑才会出现的问题 | 上一档卡在哪道门（只报最高通过档） |
| 耗时与限制 | 分钟级；不占配额 | 每项约 1–5 小时 + 排队；**不限次数**（受每人 8 卡上限约束；服务常驻，只排一次队） | 约 18 小时；**每天 2 次** |
| 谁批准 | Claude | Claude（用户授权） | Claude（用户授权），每次向用户汇报 |
| 入口 | `scripts/replay_chains.py --case-file …`（L1 替身环境） | `scripts/l2.py add <config>`（见 tests/L2.md） | `scripts/submit_official.sh A\|B` |
| **晋级条件** | TEST_PLAN 里相关的 L1 用例全部 pass（IF-*、D1-01/03/05/08/10 等），0 崩溃、0 错误 | 同一个配置：开发集临界 N ≥ 当前最好配置，没有门变差；能力抽检不退步；**发布测试**（用要提交的镜像和原文命令、正式爬梯、估计的正式口径）通过 | — |

## L2 用法
见 [L2.md](L2.md)：`scripts/l2.py configs / add / new / ls / pause / resume`。配置登记在 `scripts/session_a/configs.json`。

## 对照表（让三级之间可以换算）
每做一次 L3 提交，就把同一配置在 L2 发布测试里的结果和正式结果并排记下来，攒成换算关系（开发集 N 对应正式 N 多少、能力分偏差多大），同时拿来校验模拟器。
