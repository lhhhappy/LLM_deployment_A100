# vllm 101 — 在最后一个角色边界保留 KDA 检查点

独立候选，**默认关闭**，不在冻结基线里。对应 SGLang 101 要解决的同一问题（在角色边界保留 KDA 状态），实现与 SGLang 无关，且兼容 MTP（SGLang 开 MTP 时关闭了 101）。

## 问题（实测）

vLLM 的混合前缀缓存只能在"保留了 KDA 状态"的位置续算。默认（`align` 模式、保留间隔 0）每个请求只在提示词末尾的块边界保留一个状态，MTP 下再退一块。
而本负载的提示词在末尾之前分叉：每个请求末尾有约 430 token 的 `<|user|><system-reminder>…` 注入块，下一轮把它换成助手回复，
所以下一轮与本轮只共享到最后一个 `<|user|>` 之前，只能退回更早的状态。开发机实测、复用模型估算见 [R28](../../../research/claude/vllm/R28_vllm_scheduler_vs_R27.md)
（八卡长链集估算：默认约 15.4M token 重算 → 本机制配合 `--prefix-match-unit 64` 约 0.7M；为无淘汰假设下的模型估算）。

## 做法

设 `r` 为提示词里最后一个开轮 token（`<|user|>` 或 `<|observation|>`）的下标，`u` 为前缀匹配单元（`--prefix-match-unit`）。
下一轮的全注意力匹配到达 `⌊r/u⌋·u`，MTP（EAGLE 丢块）再退一个单元，所以 Mamba 状态必须恰好在 `C = ⌊r/u⌋·u − u`（无 MTP 时不减）。

1. **调度器**（`Scheduler._role_checkpoint_positions`，请求加入时算一次）：从末尾向前找 `r`，得到键位置 `⌊r/u⌋·u` 与状态位置 `C`；
   `C` 不大于 0 或不在提示词末尾停点之前时不设。`_mamba_block_aligned_split` 把 `C` 加为分块停点（与上游"共享前缀交汇点"停点同一处理）。
2. **Mamba 组**：分块结束在 `C` 时，走上游已有的块内部分状态登记与写时复制路径登记该状态；稀疏保留时 `C` 列为必保留位置。
3. **全注意力类各组**（MLA、索引器）：在 `⌊r/u⌋·u` 处给所在块附加一个部分键。缺这一步时，追问请求的全注意力匹配只能到块边界，检查点不可达（开发中的 CPU 测试发现并修正）。
   生命周期与上游的末尾部分键相同：该位置算完后**每一步**都登记一次（已存在时不做事），排在末尾键之后。原因是块池在两种情况下会删掉一个块的全部键：
   给它登记更长的部分键，以及解码把它填满、升级为满块（`BlockPool.cache_full_blocks`）。只在提示词算完那一步登记时，解码跨过该块末尾后角色键就丢了，
   追问命中退回更早的状态（Codex 独立 CPU 复核发现：B512/u64、提示 2551、解码 128 后命中 2048→1536）。

## 开关与校验

- `VLLM_AX_MAMBA_ROLE_CHECKPOINT_TOKEN_IDS`：逗号分隔的 token id，GLM-5.3-Flash 为 `154827,154829`；为空或未设即关闭，所有新分支不执行，行为等于底包。
- 需要：前缀缓存、Mamba `align` 模式、`--prefix-match-unit` 小于 Mamba 块（并为 `index_kpool` 的倍数）、无多模块 MTP。条件不满足（含关闭前缀缓存）时引擎启动即报错，不静默忽略。
- 启动机制行 `101=on:154827,154829` 或 `101=off`；因为不满足条件就起不来，服务在运行时 `on` 即实际生效。

## 代价

- 每个设了检查点的请求多一个分块停点；停点在块中间时，下一块还要先回到块边界，prefill 最多多 2 步前向（TTFT 增加这几步的时间，待八卡测）。
- 每请求多保留约 1 个 KDA 状态（八卡约 20 MB，推算），占用块池、减少可缓存前缀量。
