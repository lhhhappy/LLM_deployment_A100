## 2. 卡点

1. **复用容量（活变少）是正式区间的主杠杆，还没兑现。** 长链数据里 95% 以上的 prompt token 预期可复用（数据集算术）；状态丢了要重算 6–13 万 token，约 6–12 秒（推算）。180 把丢掉的状态存到主机内存（pod 实测 2 TB），059 已看到重算减少；还没验证主机恢复后的数值、恢复耗时（按最慢那张卡计）和对 decode 的干扰，也还没有逐次搬回的计数。
2. **开场冷启动潮。** chain 失败集中在开场：N 条冷链首同时进来，排队超过 30 秒。122 与链首准入正对这里。
3. **prefill 本身贵（活变便宜）。** R25 实测 16k token 时 Marlin 84.5 TF、Triton BF16 82 TF，MoE 慢在 TP8 切出的窄形状；正式 A 配置在 TP8 上的单块成本曲线还没有。
4. **MTP 关掉了 101/140 的 KDA 快照**（160 的守卫）。原生路径实际保留了什么还没量。
5. **必做 kernel 还没开工**：FP8 latent KV 进 sm80 TileLang DSA，整缓存约 1.75×（推算）。DCP 在 TP8 仍有 33/40 行不匹配。

## 4. 做这些时必须守住的技术约束

- **完整检查点契约**：一个位置要能复用，KV、索引键/KPool、KDA 与卷积状态、MTP 草稿状态必须在同一位置同时有效。HiCache 开启时，树只在 256 token 分组边界分裂，KDA 检查点只在精确位置发布（180 已实现）。
- **HiCache 首版只做两级**（显卡 ↔ 主机）：
  - 异步、增量、write-through；
  - 源页等 D2H 完成后才回收；
  - `--hicache-size` 按每卡计，从 32 GB 起；
  - flush 必须清掉所有层级。
- **恢复预算按最慢那张卡计**。"0.05–0.1 s 搬回一个会话"只是少竞争时的估计，不能当 p95。
- **FP8 KV**：
  - 行格式：带 scale 的紧凑行，512 B FP8 加 4 个 FP32 scale，共 528 B。
  - 容量：latent 行约 1.94×，整缓存按 12,716/7,260 ≈ 1.75× 计。
  - A100 上先软件解码成 BF16 再做 MMA；上游 raw 512B / SM89+ 的路径不能照搬。
  - 验收：对照参考路径，判据要能检出已知错误变体；覆盖高位地址、池满和 CUDA graph；TP8 真机确认。
- **DCP 放在 FP8 之后**。两者容量不能相乘（推算 DCP4+FP8 约 4.4×、DCP8+FP8 约 5.8×）。33/40 按行身份契约修，不针对个别形状打补丁。
- 驻留账本（`scripts/analysis/residency_ledger.py`）在开发集上校准失败（prefill 多算 74%）。用真实长链运行校准之前，它不参与选方案。
- 长链集每请求回放间隔均值 7.3 s、中位 2.9 s（开发集为 4.2 s / 1.6 s）。不为迎合模型去调整等待。
